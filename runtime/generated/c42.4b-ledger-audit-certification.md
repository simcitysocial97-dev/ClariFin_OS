## Schema Constraints

The ledger_transactions table has protective constraints that prevent certain violation types at the application layer:

| Constraint | Column | Impact |
|------------|--------|--------|
| Generated column | `debit = CASE WHEN type='debit' THEN amount_paise ELSE 0 END` | Cannot insert negative debit |
| Generated column | `credit = CASE WHEN type='credit' THEN amount_paise ELSE 0 END` | Cannot insert negative credit |
| Unique constraint | `hash_signature` | Cannot create duplicate hashes |

**Implication:** The audit engine's checks for `NEGATIVE_DEBIT`, `NEGATIVE_CREDIT`, `DUAL_ENTRY`, and `DUPLICATE_HASH` are defensive - they would only trigger if corruption bypasses the schema (direct SQL manipulation or foreign database).
