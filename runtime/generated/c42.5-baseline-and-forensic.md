## M9-C42.5-A — Forensic Investigation (Step 2)

### Where `MUTANT_NAME` is expected

`mutmut 3.7.0` (`/home/.../.venv/lib/python3.12/site-packages/mutmut/__main__.py`):

- Line 1306: `print_time_estimates` — `mutant_names` **optional**
- **Line 1330: `tests_for_mutant` — `mutant_name` REQUIRED (nargs=1)**
- Line 1718: `show` — `mutant_name` **required** (nargs=1, default)
- Line 1728: `apply` — `mutant_name` required

The exact CI error string **`Error: Missing argument 'MUTANT_NAME'`** is a Click error
emitted when a command with a `required=True` positional `mutant_name` is invoked
without it. The only such command reached by the pipeline is **`mutmut show`**.

### First incorrect boundary

**`.github/scripts/run_mutation_selective.sh:68`**

```bash
mutmut show   > "$MUTATION_OUTPUT_DIR/surviving-mutants.txt" 2>&1 || true
```

`mutmut show` **requires a mutant name**. It does not accept "show all".
Invoking it with no argument produces exactly the CI error. It is masked by `|| true`,
so it does not abort the script — but it proves the runner was invoking an
API-incompatible command and was producing no-useful-survivor output.

Secondary defect (same file, line 69):
```bash
mutmut junitxml 2>/dev/null > "$MUTATION_OUTPUT_DIR/mutation-junit.xml" || true
```
`junitxml` is **not a command** in mutmut 3.7.0 (verified: `No such command 'junitxml'`).
Also masked by `|| true`.

### Why the full run still collapsed

1. `mutmut run` with no positional runs the **entire** `src/engines/` scope
   (16k+ mutants). The runner string is `python3 -m pytest` (no test path), which
   triggers repo-wide discovery — extremely slow, ~30 min "Generating mutants"/run.
2. `mutmut show` (no arg) fails → error string in log.
3. `mutmut results` is the only reliable evidence collector; its parse in the script
   (`grep -oP 'Killed:\s+\K\d+'`) depends on a human-readable summary line that
   mutmut 3.7.0 does **not** emit in the same shape, so counts collapse to 0.
4. `mutation-summary.json` may be written with 0/0/N/A; the workflow's classify step
   then emits `mutation_score=N/A` and `killed=0` — and the gate treats "missing file"
   as `exit_code=1` (infrastructure) but the **summary still says `Score: N/A%`**
   which downstream readers misread as a 0% quality result.

### Local smoke defect (independent, confirmed)

`.github/scripts/run_mutation_local_smoke.sh:103`:
```bash
"$MUTMUT" run "$TARGET"   # TARGET="compute_outstanding"
```
`mutmut run [MUTANT_NAMES]...` treats positionals as **mutant names**, not function
selectors. `compute_outstanding` matches no mutant name, so mutmut runs the **entire**
`src/engines/` scope — the "bounded smoke" was never bounded. It also inherits the
`mutmut show`/`junitxml` incompatibilities when collecting evidence.

### Root cause (with evidence)

The mutation pipeline was built against an **obsolete mutmut 2.x mental model**
(`paths_to_mutate`, `tests_dir`, `mutmut show` lists all, `mutmut junitxml` exists)
while the pinned toolchain is **mutmut 3.7.0**, whose CLI contract is different
(`source_paths` in `[tool.mutmut]`, `mutmut show` needs a name, no `junitxml`).
This is a **mutation execution/integration contract defect**, not a test-quality
problem. It manifests identically locally and in CI because both use mutmut 3.7.0.

### Reproduction

Clean-room sandbox (top-level importable module required by mutmut trampoline):
- `mutmut show` with no arg → `Error: Missing argument 'MUTANT_NAME'.` (reproduced)
- `mutmut junitxml` → `No such command 'junitxml'` (reproduced)
- valid `mutmut run` + `mutmut results --all true` → reliable
  `killed/survived/no_tests` classification (reproduced: 2/2/2).
