## 1. The Existing Policy (documented, not invented)

The project **already has** an authoritative scoring policy. It lives in
`runtime/foundation/verification/mutation_contract.py :: compute_score()` (lines 192-204):

```python
def compute_score(counts: MutationCounts) -> float | None:
    """Mutation score = killed / (killed + survived + timeout).

    Denominator excludes no_tests (no relevant test) and not_checked/suspicious
    (not evaluated). This matches the C42 baseline computation
    (4418 / (4418 + 4315 + 38) ≈ 50.6%).

    Returns None when no mutant was scored (cannot claim a score).
    """
    denominator = counts.killed + counts.survived + counts.timeout
    if denominator == 0:
        return None
    return round(counts.killed * 100.0 / denominator, 1)
```

> **No new scoring rule was invented in this phase.** All figures below were computed by calling
> the project's own `compute_score()` and `reconcile_counts()`.

### 1.1 How each status is treated

| Status | Numerator | Denominator | Documented rationale |
|---|:---:|:---:|---|
| `killed` | ✅ | ✅ | Mutant detected — the definition of success |
| `survived` | ✗ | ✅ | Executed and **not** detected — a genuine scored failure |
| `timeout` | ✗ | ✅ | Executed and decided; an evaluated non-kill (`SCORED_STATUSES`) |
| `no_tests` | ✗ | ✗ | No relevant test — suite can be neither credited nor blamed |
| `not_checked` | ✗ | ✗ | **Never executed** — no authoritative result exists |
| `suspicious` | ✗ | ✗ | Non-decisive outcome — "not evaluated" |

`SCORED_STATUSES = ("killed", "survived", "timeout")` — *"Statuses that represent a mutant that was actually executed and decided."* (line 30)

### 1.2 Accounting invariant (enforced)

```
TOTAL = killed + survived + timeout + no_tests + not_checked + suspicious
```

### 1.3 Three-gate model

| Gate | Meaning |
|---|---|
| **A** — Execution Integrity | Did mutation testing actually execute? |
| **B** — Evidence Integrity | Are all classifications accounted for? |
| **C** — Quality Threshold (80%) | Evaluated **only** if A and B pass; else "NOT EVALUABLE" |

**Threshold: 80% — unchanged by this phase.**

## 2. Is the Existing Policy Ambiguous?

**YES — but the ambiguity is *not material* to this phase's results**, because all four engines now have `not_checked = 0` and `suspicious = 0`. The only non-zero excluded category is `no_tests = 4` out of 2,406 mutants.

I state the ambiguities explicitly, with the **smallest** clarification each would need:

### AMB-1 — Completeness is not encoded in the score

`compute_score()` returns a plausible-looking number whenever `killed+survived+timeout > 0`, **even with a large `not_checked` population**. This is exactly how loan 84.2% and reconciliation 72.5% came to be reported alongside genuinely complete engines.

> **Smallest clarification:** record an explicit completeness flag with every score —
> `mutation_complete = (not_checked == 0 and suspicious == 0)` — and require every reported
> score to be labelled **COMPLETE** or **PARTIAL**.
> *This adds a label. It does not change the formula or the threshold.*

Note: `MutationResult.evidence_complete` already exists, but it is defined as `(invariant_ok and generated > 0)`, which is **`True` for a truncated run**. The recommendation strengthens the *label*, not the scoring.

### AMB-2 — `timeout` is scored but `no_tests` is not

A defensible, documented asymmetry (timeout = executed-and-decided; no_tests = nothing to credit), but it is asserted in a **docstring** rather than a project policy document.

> **Smallest clarification:** promote the docstring rule to a written policy statement. **No numeric change.**

**Policy changes made this phase: NONE.**

## 3. Complete vs Partial — the required distinction

| Term | Definition |
|---|---|
| **Complete mutation score** | Every eligible mutant received an authoritative result (`not_checked = 0` **and** `suspicious = 0`) |
| **Partial mutation score** | Some mutants remain `not_checked`/unevaluated. **Never equivalent to a complete score.** |
