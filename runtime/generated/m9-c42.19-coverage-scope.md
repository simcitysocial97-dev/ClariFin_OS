## 5. Phase 10 — The Intended 40% Gate

Origin: commit **`f0e28f0b`** (2026-07-26) — *"feat(coverage): reset threshold to 40% with exclusions + 189 new unit tests"*

| # | Question | Answer |
|---|---|---|
| 1 | **Why 40%?** | Deliberately calibrated **down from 60** to match a then-realistic measured baseline after excluding untestable modules. Commit verbatim: *"Set fail_under=40 (was 60) to match realistic baseline"*, *"Overall coverage: 49.2% (up from 31.15%)"*, *"823 unit tests pass"*. |
| 2 | **Backend-wide?** | **YES** — for the measured source population (`source = src` minus documented omits). It is an aggregate threshold. |
| 3 | **Engine code only?** | **NO.** Engine code has a separate, **higher** intended threshold of **70%**: `check_coverage_threshold.py` → `{'overall': 40, 'engines': 70, 'repositories': 40, 'services': 40}`. |
| 4 | **Legacy?** | **PARTIALLY.** A deliberate Phase-1 value explicitly annotated as temporary: `# Phase 1 thresholds (current)`, `"overall": 40,  # Will increase in Phase 2`. |
| 5 | **Enforced by pytest?** | **YES**, indirectly but effectively — `fail_under = 40` in `.coveragerc [report]`, read via `--cov-config`. Observed both `FAIL ... not reached` and `... reached`. |
| 6 | **Enforced by CI?** | **NO.** No `--cov` or `.coveragerc` invocation in any of the 13 workflows. `backend/pyproject.toml` has no coverage settings. `check_coverage_threshold.py` is unwired (already classified *"D (redundant)"* in m9-c42.11). |
| 7 | **Advisory?** | **YES in CI** (not enforced); **BINDING locally** whenever `--cov` + `--cov-config=.coveragerc` are used. |
| 8 | **Does the canonical command cover the intended population?** | **The full-suite command DOES (65.59%, PASS). The engine-only subset used by M9-C42.18 does NOT.** |

### Verdict on threshold application

> The **40% threshold is correctly calibrated** for the population it was designed for.
> It was **incorrectly applied** to an engine-only test subset in M9-C42.18.

The subset structurally **cannot** execute `services/`, `common/`, `orchestration/`, or `cashflow` code paths, so measuring a backend-wide aggregate threshold against it is a category error.
