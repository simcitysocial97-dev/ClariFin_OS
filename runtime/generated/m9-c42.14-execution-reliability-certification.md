## IMPLEMENTATION SUMMARY

### Phase 1 — Process-Group Ownership in Executor
- **File:** `runtime/foundation/verification/executor.py`
- **Change:** `subprocess.Popen(..., start_new_session=True)` + `_kill_process_group()` method
- **Mechanism:** `os.killpg(pgid, SIGTERM)` → 0.5s → `os.killpg(pgid, SIGKILL)`

### Phase 2 — Signal Propagation
- **Change:** `Executor.cancel()` calls `_kill_process_group()` before setting cancel flag
- **Mechanism:** SIGTERM → 0.5s grace → SIGKILL cascade

### Phase 3 — Timeout Handling
- **Change:** `TimeoutExpired` exception handler calls `_kill_process_group()`
- **Mechanism:** `finally` block ensures cleanup on any exception path

### Phase 4 — Mutation Runner Cleanup
- **File:** `runtime/foundation/verification/mutation_runner.py`
- **Change:** Replaced `subprocess.run()` with `Popen(start_new_session=True)`
- **Mechanism:** Same process group kill logic in timeout handler and `finally` block
- **Safety:** Existing `_MutationSafety` context manager preserved for config restoration

### Phase 5 — CI Cancellation Behavior
- **Analysis:** GitHub Actions sends SIGTERM to job's process group on cancellation
- **Result:** Executor/mutation runner process groups receive signal → clean tree termination
- **No CI changes needed** — behavior is deterministic and matches local

### Phase 6 — Evidence Recording
- **Executor:** `runtime/generated/execution/lifecycle-events.jsonl`
- **Mutation Runner:** `backend/tests/generated/mutation/mutation-lifecycle-events.jsonl`
- **Events:** `process_group_killed`, `mutation_process_group_killed` with PGID and signal details
