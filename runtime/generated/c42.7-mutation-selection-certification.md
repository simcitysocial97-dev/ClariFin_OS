### What was investigated

1. **Trampoline mechanism verified:** Created a manual mutation (`min` → `max` in `compute_utilization`) in the real source, ran pytest — 6 tests FAILED. Mutation IS effective when applied.
2. **Trampoline dispatch verified:** Set `MUTANT_UNDER_TEST=engines.credit_card_engine.utilization.x_compute_utilization__mutmut_5` directly — mutant dispatched but was EQUIVALENT (only changed error message text), tests passed. | C42.6 Claim | Empirical Finding |

## Phase 5 — Test-Selection Proof

**Evidence that selection works:**
- Debug output captured during `utilization.py` run shows per-mutant invocation:
  ```
  python -m pytest "-vv" "--rootdir=." "--tb=native" "-x" "-q" ...
      tests/unit/engines/credit_card/test_credit_card_engine.py::TestUtilizationEngine::test_utilization_zero_limit_zero_utilization
      tests/unit/engines/credit_card/test_credit_card_engine.py::TestUtilizationCaps::test_compute_utilization_half_limit
      tests/properties/credit_card_engine/test_billing_properties.py::test_compute_utilization_math_accuracy
      ...
  ```
- 8 specific engine tests selected and executed per mutant — NO full-suite fallback.
- Manual MUTANT_UNDER_TEST=... activation proved trampoline dispatch functions.

**Evidence of test ineffectiveness (not selection failure):**
- Manual `min` → `max` mutation in `src/engines/credit_card_engine/utilization.py` caused 6 of 8 tests to FAIL.
- Yet all 52 mutmut-generated `compute_utilization` mutants survived — because mutmut 3.7.0 does NOT generate a `min`→`max` swap for this expression (default mutators miss it), and the generated mutants (string changes, value constants) are caught by none of the assertions.

**Conclusion:** Tests ARE effective for SOME mutations (proven manually) but mutmut 3.7.0's default mutator set doesn't generate those high-leverage mutations, AND existing tests lack precise value assertions for the lower-leverage mutants.
