## 1. Executive Summary

C42.27 transforms the verification framework from a *test-selection
runner* into an **evidence-aware verification graph and planning
system**. The framework can now answer:

> *What is the minimum verification necessary to make a defensible
> certification decision for this repository state, and what
> previously generated evidence can safely be reused?*

This is a permanent architectural shift. Subsequent phases
(C42.28+) can build the Diagnostic & Forensic Agent on top of
this layer without re-deriving the verification logic.

## 3. Architecture overview

```
Repository Change
       │
       ▼
Describe change (impact_rules-style)
       │
       ▼
EvidenceAwarePlanner
       │
       ├─── For each component in C42.26 population:
       │      • Apply Change → ComponentMeasurement
       │      • Apply INVALIDATION_RULES (14 enumerated rules)
       │      • Decide reuse (reusable / reusable_aggregate /
       │        reusable_with_revalidation / no_evidence /
       │        invalidated_*)
       │
       ├─── Drift detection (C42.24 regression test):
       │      • For every capability in the population:
       │        surface present? source present? executable binding?
       │      • Block certification if any drift detected
       │
       ├─── Aggregate derivation:
       │      • For valid reusable measurements:
       │        score = sum(killed) / sum(scored) * 100
       │      • This is the C42.26 principle made first-class
       │
       └─── Plan = (selected_tasks, excluded_tasks, reuses,
                    derived_aggregates, drift_blockers,
                    certification_gaps)
       │
       ▼
Correlation layer
       │
       ├─── changed_files, changed_kinds
       ├─── affected_sources, affected_capabilities,
       │    affected_components
       ├─── tested_components, untested_components
       ├─── reused_evidence, fresh_evidence_targets
       ├─── derived_aggregates
       ├─── uncertain_components, drift_blockers,
       │    certification_gaps
       └─── certifiable: bool + rationale
       │
       ▼
Certification decision
```

## 5. Measurement policy (now permanent)

C42.27 codifies the C42.26 measurement rule:

> **Targeted mutation** — whenever a specific component has
> materially changed.
>
> **Full mutation campaign** — only when one of:
> - population expansion
> - major verification architecture change
> - mutation infrastructure/toolchain change
> - mutation configuration semantics change
> - significant cross-component architectural change
> - periodic measurement checkpoint
> - final certification milestone
>
> No full campaign merely because tests were added.

The same principle will eventually apply to coverage, contracts,
E2E, and other expensive verification dimensions, wherever
evidence validity permits.

> decision for this repository state, and what previously

## 10. Forward position

C42.27 ends here. The next phases can build on this layer:

- **C42.28** — Targeted mutation campaign plumbing (a CLI
  invocation that takes the planner's selected tasks and runs
  only those).
- **C42.29** — Per-component CI evidence fingerprinting (build
  on Section 7 of the CI integration boundary).
- **C42.30** — Diagnostic & Forensic Agent (consume the
  correlation layer as the canonical source of truth).
- **C42.31+** — Evidence-driven test strengthening, informed by
  the planner's explanations rather than by hand-curated rules.

The verification architecture has become a planning-and-evidence
system, not a collection of commands that happen to run tests.
