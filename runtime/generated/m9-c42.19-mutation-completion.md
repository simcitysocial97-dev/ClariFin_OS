### 1.1 Authoritative semantics (mutmut 3.7.0)

From `site-packages/mutmut/__main__.py`:


`not_checked` is emitted when a mutant has **no recorded exit code at all** — i.e. it was never run.

**Critical disambiguation** (`__main__.py` lines 1461-1464):


A mutant whose function has **no associated tests** is recorded as **`no tests`**, *never* as `not_checked`. Therefore the claim "not_checked = no covering tests" is **provably false** for mutmut 3.7.0.

## 2. Secondary Defect Found — Post-Run Reporting Context

**Severity:** MEDIUM (evidence-reporting integrity) · **Data loss: NONE**

**Symptom:** After *any* successful `mutation --target <engine>` run, the runner prints and persists all-zero counts with `mutants_generated: 0`, `evidence_complete: false`, yet `execution_status: PASS` and exit code 0.

**Reproduced on:** `reconciliation_engine`, `credit_card_engine`, `account_engine` — it is **systematic**.

**Root cause:** `mutation_runner.py` restores the pre-run `[tool.mutmut]` block in the `finally` block (lines 605-608) **before** collecting evidence via `mutmut results --all true` (lines 638-646). The restored block usually names a *different* engine's `source_paths`. `mutmut results` resolves the population from the *current* config, finds nothing matching the wrong scope, and returns an empty set → `parse_mutmut_results()` returns all zeros.

**Proof:** Reinstalling the reconciliation config and re-running `mutmut results --all true` returned the **full 368 lines**.

**Why this was safe:** `evidence_complete` requires `counts.generated > 0`, so the zero population produced **Gate B FAIL** rather than a fake 0% score. The runner's "never emit a fake score" guarantee **held**.

**This also explains the Phase 1 baseline anomaly** (stale `mutation-summary.json`: credit_card, `mutants_generated: 0`, `PASS`).

**Remediation applied this phase: NONE (no code change).** Authoritative counts were recovered from `.meta` files and independently re-verified.

**Recommended fix (deferred):** collect `mutmut results` **before** restoring the pre-run config, or pass the engine-scoped config explicitly to the results invocation.
