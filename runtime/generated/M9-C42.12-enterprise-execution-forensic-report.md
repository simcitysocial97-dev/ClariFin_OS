## 1. EXECUTIVE DETERMINATION

ClariFin_OS executes through **one canonical spine**: `verify.sh / CI workflow → python runtime/verify.py <profile> → profiles.py (task strings) → orchestrator.py → planner.py → executor.py (shell=True, cwd=repo_root, inherited env)`. Around that spine sit four satellite execution domains — mutation (`mutation_runner.py` + mutmut 3.7.0), golden/integration/runtime shell scripts, Playwright E2E (Node-owned, spawning the backend itself), and local-only tooling (husky, verify-fast, fast-checks).

**Answer to certification question 1 — "Why does every tool execute the exact way it does?"**
Each invocation site is explained by exactly one of five mechanisms (all verified):
1. **Caller-PATH inheritance** — executor.py passes `{**os.environ, PYTHONUNBUFFERED:"1"}` (executor.py:119-131); determinism is donated entirely by `scripts/verify.sh:31` (`export PATH="$ROOT_DIR/.venv/bin:$PATH"`) or by CI's setup-python runner env.
2. **Explicit VENV_BIN prepend** — only the mutation runner does this (mutation_runner.py:354); it is the model the rest of the runtime lacks.
3. **Config-discovery by cwd** — ruff/mypy/pytest/mutmut/black all discover configuration upward from cwd or from the checked path; every cwd in the spine is pinned to repo root or backend/, so discovery is deterministic *when entered via the spine*.
4. **Bare interpreter fallback** — golden/integration/runtime scripts and Playwright's backend launch use bare `pytest`/`python3`, resolving through whatever PATH the caller supplied.
5. **Declarative inventory references** — registry.py/evidence_contract.py name `.github/scripts/*.sh` as unit provenance without executing them (F01).

**Answer to certification question 2 — "Can execution be made deterministic without changing functional architecture?"**
**YES.** All deterministic gaps found are confined to environment propagation, one tracked-file rewrite during mutation, and three dependency-governance breaks. None require topology, import-root, test, or packaging-model changes. The C42.11 Architecture-C verdict is re-affirmed with refinements (§5).

## 5. PYTHON PROJECT BOUNDARY MODEL

Resolving the contradiction between "backend source-only" and "backend/src is a package because `__init__.py` exists":

**Verified facts:**
- `backend/src/__init__.py` EXISTS, 0 bytes (stat size 0). `src` is therefore a regular importable package, not merely a directory on sys.path.
- Root `[tool.setuptools.packages.find] include=["runtime*"]` (pyproject:78-80) deliberately excludes backend; backend has NO egg-info/dist-info anywhere in .venv (verified). Backend deps are declared at root (:29-31 comment states this intent).
- Imports use top-level `from src.engines...`; enabled jointly by `backend/pyproject.toml pythonpath=["src","tests"]` (:36) for pytest, and by cwd=backend + PYTHONPATH=. for uvicorn (`src.api:app`).
- `runtime/__init__.py` DOES NOT exist → `runtime` resolves as a PEP 420 namespace package. The editable install's finder maps it explicitly (`MAPPING {'runtime': '/…/runtime'}`) with absolute host paths; additionally EVERY generated subdir (`runtime.generated.evidence.*` etc.) is importable as a namespace package — an unintended import surface over generated artifacts.
- `testing/` top-level stub package exists (`testing/__init__.py`, `testing/runtime/foundation/__init__.py` only) — INCOMPLETE, undocumented (F23).
- `servers/` exists and is EMPTY (mypy root exclude still names `servers/src/fetch/tests/`) (F24).

**Determination:** The hybrid is INTENTIONAL at the packaging level (no install, pythonpath-driven, empty marker file enabling `src` as a real package so that tools like mypy treat it consistently) and ACCIDENTAL in its remaining sharp edges (empty `__init__.py` means `import src` succeeds from any process whose sys.path includes backend/src even outside pytest; nothing asserts the intended access mode). The architecture should be PRESERVED; the alternatives and consequences are recorded, not recommended:

| Alternative | Consequence |
|---|---|
| A. Keep hybrid (status quo) | Zero migration cost; requires documenting "access via pythonpath only"; empty marker stays |
| B. Remove `backend/src/__init__.py` → true implicit namespace src | Breaks nothing today (imports unaffected) but changes mypy/IDE package semantics; risks divergence between tool assumptions — churn without payoff |
| C. Make backend an editable package | Contradicts M10 single-authority decision; adds a second install surface; rejected previously |

### 9.2 Signal / termination analysis (all VERIFIED by code reading)

| Event | Behavior | Config restored? | Source tree restored? |
|---|---|---|---|
| Normal exit / exception | finally runs | YES | YES |
| SIGINT (Ctrl-C) | KeyboardInterrupt propagates through subprocess.run → finally runs | YES | YES |
| SIGTERM | Default disposition kills interpreter; no signal handler installed | **NO — left rewritten** | NO |
| SIGKILL / OOM | Immediate | **NO** | NO |

No atexit hook, no signal.signal registration exists anywhere in mutation_runner.py (verified by full read).

### 9.3 NEW finding F04 — restore scope is repo-wide in full mode

`_restore_source_tree(cwd, "." if mode=="full" else smoke_relpath)` (:366): for full mode scope="." makes `git status --porcelain .` enumerate **every dirty tracked file in the repository**, and each gets `git checkout --`. Any developer's unrelated uncommitted edits anywhere (e.g., frontend TS, runtime code, this very report's neighbors) would be silently reverted by running a local full mutation campaign. CI is unaffected (clean checkout). Additionally the target-mode branch restores the SMOKE directory scope (`backend/tests/mutation_infra`) rather than the mutated engine path — an inconsistent latent no-op that only works today because mutmut 3.x mutates the `mutants/` copy, never originals.

### 9.4 Why dynamic config generation exists (root cause, confirmed)

mutmut 3.7.0 has no `--config-file`; even `--help` crashes outside a config-bearing cwd (reproduced: traceback through `Config.get().use_setproctitle` from repo root). Per-engine scoping therefore REQUIRES a discoverable config file whose content changes per run. Alternatives evaluated (consistent with C42.11 §10.3, plus this pass's evidence):
- temp-dir config + absolute source_paths: plausible BUT unproven for `also_copy=["src"]` relative resolution and mutants-dir placement (U-class);
- monkeypatching mutmut Config internals: couples to private API;
- env-var configuration: not supported by 3.7.0;
- keep in-tree rewrite + harden: add SIGTERM handler + atexit + post-run `git status --porcelain backend/pyproject.toml` assertion (cheap, covers everything except SIGKILL).
Concurrency: two simultaneous mutation runs race on the same tracked file and cache dirs (C42.11 finding stands — VERIFIED by reading; no lock exists).

### 9.5 Trampoline patch & hypothesis suppression

conftest.py:33-61 strips the `src.` prefix before `record_trampoline_hit` (works around mutmut __main__.py assert) and registers a `mutmut_hints` hypothesis profile suppressing `differing_executors`, gated on MUTANT_UNDER_TEST so normal runs are untouched. ## 20. ENTERPRISE TARGET-STATE PRINCIPLES

1. **Single environment authority** — root `.venv` locally, runner-python in CI, both from one pyproject contract (already true; keep).
2. **Every subprocess receives an explicit environment** — no invocation may depend on caller PATH (extends mutation-runner pattern repo-wide).
3. **No tracked file is written during verification** — mutation config moves out of `backend/pyproject.toml` or gains signal/atexit/dirty-gate hardening.
4. **Restore scopes are minimal and exact** — git-restore limited to paths the tool itself touched.
5. **One config authority per tool per boundary** — ruff conflict resolved; accidental absences made explicit.
6. **Locks are enforced or honest** — either CI diffs requirements.lock against resolution, or the lock is labeled audit-only and REGENERATED before every audit run.
7. **Declared capabilities must resolve** — every command string in profiles.py must have its interpreter module installed and declared, or be explicitly feature-flagged off (schemathesis).
8. **Fingerprints cover toolchain, not just code** — cache/evidence records include interpreter + tool versions + config hashes so replay cannot mask environment drift.
9. **Process trees are owned** — timeouts kill process groups; spawned servers are tracked and reaped.
10. **Self-diagnosis is one command** — env-check extended to configuration fingerprint (ruff/black/mypy/pytest/mutmut hashes), dependency fingerprint (pip freeze vs lock diff), execution fingerprint (last run manifest), capability fingerprint (which declared commands resolve today).
