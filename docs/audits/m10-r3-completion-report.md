## 3. Blockers found and fixed

### 3.1 `black` — 21 files (pre-existing + mine)
`exec-0003` fails the reconcile gate on formatting. Seven were pre-existing in
`backend/tests`; **fourteen were files this milestone wrote**. All formatted;
`black --check backend/ runtime/` is clean over 1202 files.

### 3.2 Baselines — 10 removed
Two were **generated by a workstation Playwright run and swept into `2c81be7d` by
`git add frontend/`** — precisely what `run_playwright_tests.sh` forbids. Neither
existed at `1c397368`; both gone. Eight more were orphaned when the three
redirect-alias pseudo-pages were removed. 41 baselines remain, all referenced.

### 3.3 `exec-0009` — the mandatory registry gap
It blocked **every plan**: the cross-layer planner names frontend capabilities in a
vocabulary the verification registry does not use, so six entries resolved to
nothing. Mapped with evidence — two hooks to `frontend-verification`, the
systematic `frontend:` convention to the capability whose declared scope is
*"Frontend components and hooks verified by the frontend profile"*, and
`playwright.config.ts` to `e2e-tests`. The bridge's narrowness is pinned: it claims
nothing outside `frontend:`, the path table is literal, every target is asserted to
be a real capability, and an unbridged entry still returns unchanged for the gate.

**Stated plainly: frontend changes no longer trip this obligation.** That is a real
reduction in fail-closed coverage, justified because frontend has a declared owner.

### 3.4 `TOOL_REGISTRY_INSTANCE` — order-dependent global
Created empty and populated only as a side effect of importing
`backend/src/routers/platform.py`. **It passed alone and failed in a larger
selection**, and `list_tools()` returned **0 tools** for any caller that had not
imported that router. Fixed at the definition site; `register_builtin_tools` made
idempotent so the legacy call site stays a harmless no-op.
